# 角色與招式

一輪只扮演一個角色。括號裡是 chrome-cdp-ex 的對應指令，`<t>` 代表目標分頁；完整語法以 chrome-cdp-ex 的 `references/commands.md` 為準。

每一輪開始前先執行 `console <t> --clear`，這樣之後看到的 console 錯誤都是這一輪產生的。

## 新手

**心態**：第一次來，沒看說明，只靠畫面上看到的東西決定下一步。

**招式**
- 每到一個畫面，先在不操作的情況下回答三個問題：這頁是做什麼的？我現在該做什麼？做完會去哪裡？只要有一題答不出來，就記成問題。
- 只照畫面文字的字面意思操作。按鈕寫「確定」，卻不知道會確定什麼，就記錄下來。
- 找出主要任務的入口，並記下花了幾步。三步以上才找到，或需要用猜的，就記錄下來。
- 故意走錯一步（點錯選項、填錯欄位），看系統有沒有告訴你錯在哪、要怎麼回頭。
- 留意專有名詞、縮寫、內部用語，以及同一個東西在不同地方叫不同名字。

**找什麼**：入口藏太深、文案模糊、下一步不明確、錯誤訊息沒說怎麼修、用詞不一致。

## 亂點

**心態**：沒耐心又手殘，一直按、按錯、按到一半就跑掉。

**招式**
- 連點兩下或三下送出按鈕，檢查是否重複送出或重複建立。chrome-cdp-ex 的 `click` 和 `repeat` 都會等頁面穩定才回傳，做不出快速連點；改用 `eval <t> "(()=>{const b=document.querySelector('<sel>'); b.click(); b.click();})()"`，再用 `netlog` 或列表確認送出了幾次。
- 流程做到一半時：按上一頁（`back <t>`）、重新整理（`reload <t>`）、在新分頁開同一個網址。檢查資料是否不見、狀態是否錯亂、是否重複送出。
- 在每個輸入框依序試：空白、只有空格、500 字以上的長字串、emoji `🙃👨‍👩‍👧`、`<script>`、`' OR 1=1`、全形數字、負數、`0`、貼上含換行或格式的文字。
- 在載入完成前就點下一步，或在動畫播到一半時點擊。
- 開啟 modal 後按 Esc、點背景、再按上一頁。
- 操作中途把視窗縮小再放大（`viewport <t> 800x600`，再改回原尺寸）。

**找什麼**：重複送出、狀態遺失、當掉、畫面卡住、沒有做輸入驗證、長字串撐破版面、在不該能按的時機還能按。

## 設計師

**心態**：一像素都要計較，同一層級的元素必須長得一模一樣。

**招式**
- 每個畫面都截一張全頁截圖（`fullshot <t>`），檢查對齊、間距節奏、字級層級、顏色是否一致。
- 對同類元素（按鈕、卡片、標題）讀 computed style（`styles <t> <sel>`），比對尺寸、圓角、字重是否一致。
- 檢查 hover、focus、active、disabled 四種狀態都有設計，而且彼此看得出差別（`hover <t> <ref>`、`emulate <t> --focus`）。
- 切換深色和淺色模式，各看一次（`emulate <t> dark`、`emulate <t> light`）。
- 留意文字被截斷、圖片變形、圖示風格混用、icon 和文字基線沒對齊、空白分配不平均。

**找什麼**：不一致、不對齊、對比不足、狀態沒設計、深色模式破版、整體看起來廉價或雜亂。這類問題預設歸為 P3，除非已經影響可讀性或操作。

## 小螢幕鍵盤

**心態**：用手機，或者只用鍵盤，沒有滑鼠。

**招式**
- 用 `390x844` 和 `320x568` 把主要流程完整走一遍（`viewport <t> 390x844`）。也可以一次掃多個尺寸（`responsive-audit <t> --viewport 390x844 --viewport 768x1024`）。
- 檢查是否出現橫向捲動、元素重疊、按鈕小於 44px、固定定位的 header 或 footer 擋住內容、手機鍵盤彈出後輸入框被蓋住。
- 只用 Tab、Shift+Tab、Enter、Space、Esc 完成主要任務（`press <t> Tab`）。檢查 focus 順序是否合理、焦點是否看得見、modal 是否把焦點限制在 modal 內、關閉後焦點是否回到原本的位置。
- 檢查圖示按鈕有沒有可讀的名稱（看 `perceive` 輸出的 accessible name）。

**找什麼**：跑版、點不到、鍵盤無法完成任務、焦點消失、沒有可讀名稱。

## 惡劣環境

**心態**：網路很差、後端不穩、時間不對。

**招式**
- 用慢網路走一次主要流程（`throttle <t> slow-3g`），檢查有沒有載入提示、能不能重複送出、會不會一直卡在 spinner。測完記得 `throttle <t> off`。
- 在流程中途斷網（`throttle <t> offline`），然後恢復，看資料會不會遺失、有沒有提示。
- 讓 API 回傳 500、401、空陣列、超大資料量（`mock <t> add …`，語法見 commands.md），檢查錯誤訊息和恢復方式。
- 凍結或位移時間（`clock <t> freeze`、`clock <t> offset`），檢查時間顯示、過期邏輯、時區。
- 查看效能（`status <t> --vitals`），留意明顯的 LCP、CLS、INP 問題。

**找什麼**：沒有錯誤處理、錯誤訊息看不懂、spinner 永遠不停、資料遺失、版面跳動、時間顯示錯誤。
