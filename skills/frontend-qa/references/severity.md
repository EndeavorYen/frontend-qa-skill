# 嚴重度與類別

## 嚴重度

依「對使用者的影響」判斷，而不是看修起來有多難。

| 等級 | 定義 | 例子 |
|---|---|---|
| **P0** | 資料遺失或損壞、安全問題、整個 app 或主要流程完全無法使用 | 送出表單後資料消失；連點兩下就扣款兩次；登入後白畫面 |
| **P1** | 主要任務被卡住，或需要使用者自己想辦法才能繞過 | 手機上送出按鈕被 footer 擋住；送出時斷網且畫面完全沒有反應（無法判斷寫入有沒有成功）；錯誤後只能重新整理才能恢復；必填欄位沒標示，導致送出一直失敗 |
| **P2** | 任務做得完，但有明顯摩擦、困惑或錯誤 | 錯誤訊息只寫「發生錯誤」；沒有 loading 提示，使用者以為當掉；console 有錯誤；次要功能壞掉 |
| **P3** | 挑剔類：不影響完成任務，但影響質感或一致性 | 間距不一致；按鈕圓角不同；文案語氣不一；hover 狀態缺漏 |

### 判斷原則

- 拿不定主意時，問自己：「第一次來的使用者遇到這個問題，會不會放棄這個任務？」會 → 至少 P1；會猶豫但最後完成 → P2。
- 送出時斷網且畫面沒有任何反應，不是 P2 的「沒有 loading」。使用者無法判斷寫入有沒有成功，至少是 P1，因此要有重現腳本。
- 影響範圍大的就往上升一級：例如同一個 P3 問題出現在全站每一頁，可以升為 P2，並在描述中說明影響範圍。
- 正式環境的資料問題、金流問題、權限問題，最低就是 P1。

## 類別

每個問題標一個主要類別，有需要可以再加一個次要類別。

| 類別 | 意思 |
|---|---|
| `bug` | 功能行為和預期不符、出現錯誤、當掉 |
| `斷點` | 流程走不下去，或走到死路 |
| `邏輯` | 行為本身前後矛盾，或不合常理（例如顯示「已儲存」但其實沒有儲存） |
| `UX` | 操作做得到，但很費力、容易困惑、容易犯錯 |
| `UI` | 視覺、排版、一致性 |
| `文案` | 用詞、語氣、錯字、意思不清楚 |
| `a11y` | 無障礙：鍵盤操作、焦點、可讀名稱、對比 |
| `效能` | 慢、卡、版面跳動 |
| `RWD` | 特定視窗尺寸下才出現的問題 |
