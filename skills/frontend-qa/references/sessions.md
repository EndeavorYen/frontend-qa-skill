# 分 session 執行

成本大約是「輪數 × 平均對話長度」。所有測試輪都在同一個對話中跑的話，對話會一路變長，後面每一輪都要重讀前面的紀錄。分 session 執行時，每個測試輪和體檢各用一個新的子 session，只帶入那一輪需要的內容，所以每個 session 的對話都很短。

代價：
- 會開多個子代理（subagent），所以一定要先取得使用者同意
- 各輪看不到上一輪的細節，只看得到 `findings.md` 的標題清單，所以主 session 合併時要另外去除重複

## 取得同意

步驟 0 和深度一起問一次：「要不要分 session 執行？每個測試輪和體檢會各開一個子代理，依序執行，可以降低成本。」

- 使用者同意：用分 session 執行
- 使用者不同意、沒有回答，或執行環境沒有開子代理的工具：用單一 session，照原本的步驟 2、3 執行
- 無人值守：只有指令明確允許分 session（例如「允許分 session 執行」「可以開子代理」）時才用；沒寫就用單一 session

在 `report.md` 開頭記下用的是哪一種模式。

## 主 session 做什麼

主 session 負責步驟 0、1、4、5、6，以及依序派出子 session。

1. 步驟 1 完成後，覆蓋地圖、`report.md` 的估算都已經寫好
2. 依開啟的測試輪順序，一次派出一個子 session，等它結束再派下一個。**不要並行**：各輪共用同一個瀏覽器分頁和同一份 app 資料，並行會互相干擾
3. 每個子 session 結束後，讀它回報的一行摘要，並確認覆蓋地圖那一欄符合步驟 2 的完成條件：沒有 `☐`、每個 `➖` 都附理由、每個 `⛔` 都附工具軌編號。不符合的話，再派一次同一輪，只帶入還沒完成的列；重派一次後仍沒完成，就把剩下的格子標成 `➖ 子 session 未完成`，並在 `report.md` 寫明
4. 體檢有開的話，最後派一個體檢子 session
5. 全部結束後，加總各子 session 回報的 turns 和分鐘，作為 `report.md` 的實際成本，再做步驟 4 的合併與分級

## 子 session 帶入什麼

只帶入以下內容，不要把主 session 的對話紀錄或其他輪的細節傳過去：

- 執行目錄的路徑，以及 `coverage.md` 的內容
- 步驟 0 的目標 URL 和分頁 id、測試帳號（含密碼或登入方式）、環境、範圍、禁止動作、視窗尺寸、深度，以及工具軌是否開啟
- 體檢子 session 另外帶入體檢程度（輕 / 標準 / 深，依 [depth.md](depth.md#預設面項) 或使用者的指定）
- 這一輪需要的 reference：
  - 測試輪：`personas.md` 開頭的說明和這一輪的段落、`severity.md`、`report-template.md` 的 findings.md 格式；`狀態` 這一輪再加 `state-checklist.md`
  - 體檢：`ux-review.md`
  - 工具軌開啟時，每一輪都帶 `tool-track.md`
- `findings.md` 目前的標題清單（`grep '^### F' findings.md` 的結果，一行一筆），用來避免重複回報
- SKILL.md 的「歸因規則」「證據規則」「護欄」三節

## 子 session 的產出

- 新發現的問題寫進 `findings.md`，編號接在現有最大的 F 編號之後
- 把 `coverage.md` 中自己那一欄的 `☐` 改成 `✅`、`➖ <理由>` 或 `⛔ <工具軌編號>`。不要改其他輪次的欄。清掉的檢查不把路徑寫進輪次欄；只有「備註」欄可以放證據，在原有內容後面追加 `證據：<這輪>→<路徑>`（見 [report-template.md](report-template.md#coveragemd)）
- 工具問題寫進 `tool-track.md`，判斷不出來的寫進 `unattributed.md`。`unattributed.md` 的每一筆都要有證據，至少一種：`shots/` 的截圖路徑、重現腳本，或 `probe-result.json` 的那一筆（見 [report-template.md](report-template.md#unattributedmd)）
- 體檢子 session 寫 `ux-review.md`，並更新覆蓋地圖的 `體檢` 欄。體檢的依據必須是實際操作（見 [ux-review.md](ux-review.md)），所以體檢子 session 要先讀 `findings.md` 的完整條目和 `shots/`，再把每個畫面的主要任務自己操作一遍，才開始評分
- 結束時只回報一行：`<輪名>：新增 F<a>–F<b>，☐ 剩 <n> 格，用了 <n> turns、<n> 分鐘`（拿不到用量時寫「未知」）

## 合併與去重

步驟 4 由主 session 做。因為各輪只看得到標題，同一個問題可能被不同輪各記一次：

- 同一個畫面、同一個現象，就算是重複；描述的角度不同也一樣
- 合併時保留最小的 F 編號，在那一筆加上一行 `- 合併：F12、F27`，並把被併掉那幾筆的證據搬到這一筆
- 被併掉的條目從 `findings.md` 刪除，不要留著，否則報告的嚴重度統計會重複計算
- 體檢中引用到被合併的 F 編號，要改成保留下來的編號
