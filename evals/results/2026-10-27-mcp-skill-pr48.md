## 方法差異與限制

- **n=1**，只跑一次完整 black-box
- **不是隔離的 run**：這個 runner 前幾輪讀過 ANSWER-KEY 和舊結果檔（包括 B2 被漏掉的紀錄），這次刻意在手機尺寸做了出錯狀態下的遮擋檢查。21/21 很可能偏高，不能當成 skill 本身的進步
- **探測和 MCP 不是同一個瀏覽器**：文件的 9222 設定要 MCP server 帶 `--browser-url`，這個環境的 MCP server 是既有連線，不能在 run 裡改。所以探測連 9222 的 Chrome（自己登入），MCP 工具操作 MCP 自己的 Chrome。對探測結果沒有影響，但 checkpoint 和登入狀態不共用（工具軌 T1）
- 探測第一次因為送出 selector 寫成 `button[type=submit]`（按鈕沒有 type）有 3 個 probe-error，改 selector 重跑（T3）；探測對帳號欄 selector 含 `password` 字樣誤報明文密碼（T2）
- **runner 不同**：10-09 那欄是外部 runner 的計數，有 token；後三欄是 agent runner 直接照 SKILL.md 操作，沒有 token 計數。步數和時間口徑不同，不能直接相除
- Critic 重做是批次：F6、F11、F19、F20 一個 `evaluate_script` 依序做，不是每條各還原一次；F8 在同一次頁面載入內做 2 次
- Playwright 沒裝，`repro/*.spec.ts` 都沒跑
- 沒有測：詳情頁 API 失敗、登入 API 斷網
