# 小訂單（http://localhost:4174）挑剔使用者測試報告

測試日期：2026-10-06
工具：chrome-cdp-ex（CDP_PORT=9445，既有分頁）
視窗：桌機 1440×900、手機 375×740

**結論：** 這個 app 能跑，但連基本的資料正確性都守不住：「已完成」篩選結果是錯的；表單接受負數和 0；連點會建立重複訂單；沒有備註或不存在的訂單，詳情頁會壞掉；設定頁的「儲存」其實什麼都沒存；頁尾兩個連結都是死連結。下面依嚴重度列出，每項都附重現步驟與實測結果。

嚴重度：
- **P0**：資料錯誤或功能失效
- **P1**：明顯 bug 或斷點
- **P2**：UX 不順或不合邏輯
- **P3**：UI 醜或需要挑剔的小地方

---

## P0：資料錯誤或功能失效

### 1. 「已完成」篩選顯示待處理訂單
- 步驟：訂單列表 → 點「已完成」。
- 實測：列出 #1 王小明（待處理）、#2 陳美玲（已完成）、#3 Lin-Corp（待處理）。只要不是「已取消」都會被列出。
- 預期：只列出狀態是「已完成」的訂單。

### 2. 建立訂單接受負數、小數和 0
- 步驟：建立訂單，數量填 `-2.5`、單價填 `-100` → 送出。
- 實測：建立成功（#4），小計顯示 **NT$ 250**（負負得正）。數量 `0`、單價 `0` 也能送出（#5～#7）。
- 欄位下方明明寫「數量必須是正整數」，但實際上完全沒有檢查。單價也沒有任何限制。

### 3. 連點「送出訂單」會建立重複訂單
- 步驟：填好表單，快速連點送出 3 次。
- 實測：一次建立 #5、#6、#7 三筆完全相同的訂單。送出期間按鈕沒有停用，也沒有 loading 狀態。

### 4. 沒有備註的訂單，詳情頁拋出例外
- 步驟：打開 `#/orders/3`（種子資料 #3 沒有 `note` 欄位）。
- 實測：Console 出現 1 個 exception。「備註」欄位是空白，連「（無備註）」都沒顯示。原因是 `order.note.trim()` 遇到 undefined 就直接拋錯。

### 5. 不存在的訂單顯示垃圾畫面
- 步驟：打開 `#/orders/999`（API 回 404）。
- 實測：畫面顯示「工單 #undefined」、小計「NT$ 非數值」、狀態「undefined」，Console 有 2 個 exception。沒有「找不到此訂單」的提示，也沒有提供返回的路。

### 6. 設定頁的「儲存」是假的
- 步驟：顯示名稱改成「新名字」、每頁筆數改成 50、取消勾選 Email 通知 → 儲存 → 出現「已儲存」toast → 重新整理。
- 實測：三個值全部還原（名稱是原帳號、筆數 10、通知已勾選）。右上角的使用者名稱也一直沒變。
- 另外，「每頁筆數」在列表上根本沒有作用，列表沒有分頁。這是在騙使用者。

### 7. 頁尾「說明」「聯絡我們」都是死連結
- 實測：點下去都只顯示「找不到頁面」。
- 未登入時點這兩個連結，會直接被踢回登入頁，等於沒反應。

## P1：明顯 bug 或斷點

### 8. 刪除已不存在的訂單，UI 照樣當作成功
- 實測：對話框開著時，訂單已經被刪掉（例如在另一個分頁刪除）。這時按「刪除」，API 回 404，UI 不顯示任何錯誤，直接關閉對話框。
- 所有 fetch 都沒有檢查 `res.ok`，也沒有任何錯誤處理。

### 9. 刪除按鈕連點會送出多次 DELETE
- 實測：在確認框連點「刪除」兩下，送出 2 次 `DELETE` 請求。刪除期間按鈕沒有停用。

### 10. 快速切換篩選後，點一次刪除會跳出兩個對話框
- 步驟：在網路稍慢的情況下（實測時把請求延遲 300ms），快速連點「待處理」再點「全部」，然後點任一個 🗑。
- 實測：同時疊出 **2 個** 刪除確認框。原因是舊請求晚回來時，又在同一個 `#list` 上多掛了一次 click listener。

### 11. 後端接受空白訂單，列表出現空行
- 實測：`POST /api/orders` 送 `{}`，後端回 201，建立出 #8。
- 列表上 #8 是一列只有編號的空行。詳情頁的客戶、品項、數量都是空白，小計顯示「NT$ 非數值」。前端擋了，但後端完全沒有驗證。

### 12. 登入只檢查「有沒有填」，空白密碼也能登入
- 實測：密碼只填一個空格就能登入。帳號已經做了 trim，密碼卻沒有，邏輯不一致。
- 帳號填 `<b>挑剔王</b>` 也照收，結果右上角直接顯示 `<b>挑剔王</b>` 這串字（有跳脫，沒有 XSS，但很難看）。

### 13. 刪除確認框不能用鍵盤操作
- 打開對話框後，焦點留在 `<body>`，沒有移進對話框，也沒有 focus trap。
- 按 Esc 不會關閉（實測按 Esc 後對話框還在）。

### 14. 刪除按鈕是 `<div>`，不是 `<button>`
- 🗑 用的是 `<div class="icon-btn">`：tabIndex 是 -1，沒有 aria-label。鍵盤使用者無法刪除，螢幕閱讀器只會唸出「🗑」。

### 15. 手機版最後一列被固定 footer 擋住
- 實測：375px 寬度捲到最底，最後一列的底邊在 636px，footer 從 620px 開始，最後一列被蓋住。
- 原因：手機版 footer 高 120px，但 body 的 padding-bottom 只有 64px。而且固定 footer 一直佔掉約 16% 的螢幕。

## P2：UX 不順或不合邏輯

16. **訂單建立後就改不了**：沒有編輯功能，也不能改狀態（標記完成或取消）。「已完成」「已取消」兩個篩選對新訂單永遠用不到。詳情頁也沒有刪除按鈕。
17. **錯誤訊息只有「發生錯誤」**：表單驗證失敗時只顯示這四個字，不說是哪個欄位，欄位也沒有紅框，必填欄位也沒有標示。修正欄位後錯誤訊息還一直留著，要等再次送出才會消失。
18. **名稱不一致**：列表、按鈕和導覽列都叫「訂單」，詳情頁標題卻叫「**工單** #3」。
19. **空狀態只剩表頭**：「已取消」篩選沒有資料時只顯示一列表頭，沒有「目前沒有訂單」之類的提示。表頭欄寬也跟著跳動。
20. **篩選狀態沒有放進 URL**：重新整理後回到「全部」，也不能分享篩選結果。
21. **頁籤標題永遠是「小訂單」**：不管在哪一頁都一樣，開多個分頁時無法分辨。
22. **導覽列沒有標示目前頁面**：沒有 active 樣式。左上角的品牌「小訂單」是 `<span>`，點了不會回首頁。
23. **刪除確認框沒寫要刪誰**：只寫「刪除訂單 #7？」，沒有客戶名或品項，容易刪錯。
24. **列表與詳情頁沒有單價**：只有小計。像 #4 小計 NT$ 250 這種錯誤，從畫面上看不出是怎麼算出來的。
25. **長客戶名在列表被截斷，但沒有 tooltip**（`title` 是空的），看不到全名。
26. **「找不到頁面」只有一行字**：沒有返回首頁的連結。
27. **登入狀態存在 sessionStorage**：開新分頁就要重新登入。
28. **「儲存」toast 正好蓋住「登出」按鈕**：toast 範圍 (1347,16)–(1424,58)，登出按鈕 (1352,12)–(1416,52)，兩秒內按不到登出。toast 也沒有 `role="status"`，螢幕閱讀器讀不到。
29. **沒有搜尋和排序**：訂單一多就只能用肉眼找。

## P3：UI 醜或需要挑剔的小地方

30. **詳情頁長客戶名衝出卡片**：#3 的客戶名超出卡片右邊框（`.card dd { white-space: nowrap }`）。
31. **欄位提示幾乎看不到**：「數量必須是正整數」的顏色是 `#c8c8c8`，背景是 `#f6f7f9`，對比約 1.6:1，遠低於 WCAG 要求的 4.5:1。
32. **按鈕圓角不一致**：主要按鈕 4px，次要按鈕 12px。「取消」和「送出訂單」並排時一圓一方，看起來像兩套設計系統。
33. **訂單編號是瀏覽器預設的藍色底線連結**（`rgb(0,0,238)`）。「← 回列表」也一樣，跟整體設計不搭。
34. **登入前後 header 高度會跳**：登入頁 48px，登入後因為多了「登出」按鈕變成 66px，整頁往下跳。
35. **手機版 header 換成三行（143px）**：「登出」單獨佔一行。表格需要橫向捲動才看得到小計、狀態和刪除，但畫面上看不出可以捲動。「數量」表頭被擠成直排，品項逐字換行（「機械／鍵盤」「27／吋螢／幕」）。
36. **登入頁表單沒有置中**：靠左擺在大片空白裡，登入按鈕只有 64px 寬，看起來很小氣。
37. **🗑 用 emoji 當圖示**：不同平台顯示不一致，也沒有 hover 或危險色的提示。所有按鈕都沒有 hover 樣式。
38. **「載入中…」只是一行灰字**：沒有 spinner 或骨架畫面，切換篩選時表格會整個閃一下。
