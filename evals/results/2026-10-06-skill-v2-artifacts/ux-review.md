## S1 登入
- 視覺層級 4：標題、兩個欄位、一顆主要按鈕，一眼看懂。要到 5：表單在 1440 寬的畫面中靠左（x=296–776），右側大片空白，置中或加上產品說明會更完整。
- 一致性 3：「登入」主要按鈕圓角 4px，進站後的次要按鈕是 12px（F24）。
- 排版節奏 3：手機上排得好（320×568 登入鈕在 y=303–343，未被頁尾擋住）；桌機偏左。
- 回饋 3：空白送出會顯示「請輸入帳號與密碼」，這點做得好；但沒有登入中狀態，也沒有說明「任意帳號皆可」這類測試環境提示。
- 文案 3：用語清楚；頁尾「說明」「聯絡我們」點了是 404（F4）。
- 效率 3：Enter 可以送出（以原生按鍵事件驗證），帳號欄有 `autocomplete`；深層連結登入後不會回到原頁（F15）。
- 質感 3：乾淨但很陽春，沒有品牌元素。

## S2 訂單列表
- 視覺層級 4：標題、右上角「建立訂單」、篩選、表格，主要動作清楚。
- 一致性 2：主要 / 次要按鈕圓角不同（F24）、編號連結用預設藍底線（F26）、刪除用 emoji（F28）。量化：圓角 2 種、文字色含預設藍。
- 排版節奏 2：一筆無空格長品項就把表格撐到 6203px，數量 / 小計 / 狀態被擠出畫面（F19）；手機上頁尾蓋住最後一列（F32）；空結果時欄寬跳動（F14）。
- 回饋 2：API 失敗永遠「載入中…」（F35）；刪除成功或失敗都沒有提示（F16、F37）；空狀態沒有說明（F14、F40）。要到 4：錯誤狀態加重試、刪除後顯示 toast、空狀態加「建立第一筆」。
- 文案 3：欄位名稱清楚；「已完成」篩選結果不符字面（F12）。
- 效率 2：篩選壞了兩個（「已完成」含待處理、「全部」不含已取消：F12、F39）；沒有分頁或搜尋（F39）；刪除鍵盤到不了（F30）。
- 質感 2：資料可能因為篩選錯誤而不可信，這是最傷信任的地方。

## S3 訂單詳情
- 視覺層級 3：欄位以「標籤 / 值」排列，可讀；但頁面沒有任何動作（不能改狀態、不能編輯、不能刪除），使用者看完只能回列表。
- 一致性 2：標題寫「工單」，其他地方都寫「訂單」（F7）；沒有備註時有時顯示「（無備註）」有時空白（F8）。
- 排版節奏 2：長客戶名溢出卡片（F6），手機上造成整頁橫向捲動（F33）。
- 回饋 2：不存在的編號或 API 失敗時顯示「工單 #undefined」「NT$ 非數值」（F5、F41），沒有任何說明。
- 文案 2：`undefined`、`非數值` 直接露出給使用者。
- 效率 2：死路頁面；狀態「待處理」無法在任何地方改成「已完成」，所以「已完成」「已取消」對使用者來說無法達成。
- 質感 2：壞資料直接露出，看起來像未完成的產品。

## S4 建立訂單
- 視覺層級 4：欄位由上而下、小計即時計算、主要按鈕明顯。
- 一致性 3：「取消」12px 圓角與「送出訂單」4px 並排（F24）。
- 排版節奏 2：手機上「送出訂單」被固定頁尾蓋住，無法捲動露出（F29）。
- 回饋 1：送出期間無任何處理中狀態（F38）；離線送出毫無反應（F36）；API 失敗卻跳到「找不到頁面」並丟掉輸入（F34）；成功也沒有提示（F10）。四種結果使用者都無法正確判斷。
- 文案 2：錯誤只有「發生錯誤」（F2）；「數量必須是正整數」常駐、極淡、而且規則實際不執行（F3、F1）。
- 效率 2：連點會建出多筆重複訂單（F18）；離開或重整表單內容消失（F20）；欄位沒有必填標示。
- 質感 2：可以建出負數量、負單價的訂單（F1、F42），對訂單系統而言這是最嚴重的信任問題。

## S5 設定
- 視覺層級 4：三個設定加一顆儲存，簡單清楚。
- 一致性 3：下拉選單灰底（瀏覽器預設），其他輸入框白底（F27）。
- 排版節奏 2：手機 320×568 時「儲存」被頁尾完全蓋住（F29）。
- 回饋 1：顯示「已儲存」但實際沒有儲存（F11，`儲存` 不發任何請求）；toast 蓋住登出按鈕（F13）。回饋說謊比沒有回饋更糟。
- 文案 3：「寄 Email 通知我」但沒有 Email 欄位（F17）。
- 效率 3：操作步驟少；但設定本身無效，「每頁筆數」也沒有作用（F39）。
- 質感 2：使用者第一次回來看就會發現設定沒存，之後不會再信任這個頁面。

## S6 找不到頁面
- 視覺層級 2：只有一行 15px 一般文字「找不到頁面」，沒有標題，看起來像載入失敗。
- 一致性 3：沿用頁首頁尾。
- 排版節奏 3：整頁空白，但沒有破版。
- 回饋 3：至少告訴使用者頁面不存在。
- 文案 3：沒有說明原因或下一步。
- 效率 2：沒有「回訂單列表」按鈕（F9）；而且頁尾兩個連結都會把人帶到這裡（F4）。
- 質感 2。

## S7 頁首 / 頁尾
- 視覺層級 3：品牌、導覽、使用者、登出位置合理；但目前頁面沒有標示（F44）。
- 一致性 3：導覽連結深色無底線，頁尾連結灰色有底線，內容區連結預設藍（F26）。
- 排版節奏 2：手機上頁尾變成 120px 固定區塊，佔螢幕 14–21%，並且蓋住主要按鈕（F29、F32）；長使用者名稱讓頁首變四行（F22）。
- 回饋 3：「已儲存」toast 放在登出按鈕上（F13）。
- 文案 3。
- 效率 2：頁尾兩個連結都是 404（F4）。
- 質感 3。

## 最值得做的 5 項改善

照「對使用者的影響 ÷ 改動大小」排序：

1. **手機版頁尾改成不固定（或主內容加上等高的 `padding-bottom`）**
   - 現況：≤480px 時頁尾 `position: fixed`、高 120px，蓋住「送出訂單」「儲存」與列表最後一列（F29、F32）
   - 建議：移除 `@media (max-width:480px)` 中的固定定位，讓頁尾跟在內容後面；若必須固定，`main` 加 `padding-bottom: 120px`。頁尾的「說明」「聯絡我們」在頁面完成前先移除（F4）
   - 預期效果：手機上主要流程恢復可用；S4、S5 排版節奏可到 4
2. **建立訂單表單：前端驗證 + 送出中狀態 + 失敗處理**
   - 現況：負數 / 0 / 小數數量、負單價都能送出（F1、F42）；連點建出重複訂單（F18）；失敗時跳到 404 並丟掉輸入（F34）；只顯示「發生錯誤」（F2）
   - 建議：數量 `min=1 step=1`、單價 `min=0` 並在送出前檢查；必填欄位加標示，錯誤寫在欄位下方；送出後按鈕立刻 `disabled` 並顯示「送出中…」；只有 `response.ok` 時才導到詳情頁，否則留在表單、保留輸入並顯示「建立失敗，請再試一次」；提示文字顏色至少 `rgb(107,114,128)`（約 4.6:1），只在驗證失敗時用紅色
   - 預期效果：堵住髒資料與重複訂單；S4 回饋、文案、效率可到 4
3. **設定頁真的儲存，或在完成前移除「已儲存」**
   - 現況：按「儲存」不發任何請求，卻顯示「已儲存」（F11）；「每頁筆數」沒有作用（F39）
   - 建議：串接儲存 API（或至少存到 localStorage），儲存成功後再顯示 toast；toast 移到不會蓋住登出的位置（例如頁面右下或表單下方，F13）；Email 通知旁顯示要寄到哪個信箱（F17）
   - 預期效果：S5 回饋從 1 到 4
4. **修正篩選邏輯並補上空狀態與錯誤狀態**
   - 現況：「已完成」含待處理（F12）、「全部」不含已取消（F39）；API 失敗永遠「載入中…」（F35）；空結果只剩表頭（F14、F40）
   - 建議：篩選用狀態代碼比對（`pending` / `done` / `cancelled`），「全部」不加條件；`fetch` 失敗時顯示「無法載入訂單」與「重試」按鈕；空結果顯示「沒有符合的訂單」與「建立訂單」連結；篩選狀態寫進網址（`#/orders?status=done`，F43）
   - 預期效果：列表資料可信；S2 回饋、效率到 4
5. **長內容與無效編號的防護**
   - 現況：長品項撐爆表格（F19）、詳情頁溢出（F6、F33）；不存在的編號顯示 `undefined`（F5、F41）
   - 建議：表格儲存格加 `max-width` + `text-overflow: ellipsis` + `title`（客戶欄已經有，品項欄比照）；詳情值加 `overflow-wrap: anywhere`；詳情頁 API 回 404 / 失敗時顯示「找不到訂單 #99」與「回列表」按鈕；標題統一用「訂單」（F7）
   - 預期效果：S2、S3 排版節奏到 4，S3 文案到 4

另外兩項影響較大、但改動也較大的：刪除鈕改成 `<button aria-label="刪除訂單 #N">` 並讓確認框接管焦點與 Esc（F21、F30、F31）；在詳情頁加上「變更狀態」，否則「已完成 / 已取消」使用者永遠做不到。
