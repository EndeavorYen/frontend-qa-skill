## 最嚴重的 5 個問題
1. F29 [P1][斷點][RWD] 手機上「送出訂單」和設定的「儲存」被固定頁尾蓋住，頁面又不能再往下捲 — 390×844 的手機幾乎無法建立訂單
2. F1 [P1][邏輯] 建立訂單的數值欄沒有驗證：數量可為 0 / 負數 / 小數，單價可為負數 / 極大值 — 直接產生 `NT$ -300` 這類髒資料，畫面上寫的「必須是正整數」並未執行
3. F18 [P1][bug] 連點「送出訂單」會建立多筆重複訂單 — POST 要 0.8 秒、按鈕不停用，手殘或網路慢就重複下單
4. F34 [P1][邏輯] 建立訂單 API 失敗時跳到「找不到頁面」，輸入全部遺失 — 使用者無法判斷有沒有成功，重填又可能造成重複
5. F11 [P1][邏輯] 設定顯示「已儲存」但沒有儲存 — 使用者以為關掉了 Email 通知，其實沒有

## UI/UX 體檢摘要
- 整體 2.5 / 5；最低分的畫面：S3 訂單詳情（2.1），其次 S4 建立訂單（2.3）
- 最值得做的 3 項改善（完整內容見 `ux-review.md`）：
  1. 手機版頁尾改成不固定（或 `main` 加 `padding-bottom`），並先移除兩個 404 連結
  2. 建立訂單表單加上前端驗證、送出中停用按鈕、只有 `response.ok` 才導頁，失敗時保留輸入並顯示可重試的錯誤
  3. 設定頁真的儲存（或在完成前不要顯示「已儲存」），toast 移開登出按鈕
