# 體檢（標準）

依據：`../state/design-context.md`（推測）。截圖：`shots/F-mobile-footer-covers-submit.png`、`shots/F-offline-submit.png`、`shots/F-modal-esc.png`、`shots/F-cancelled-empty.png`、`shots/F-order-999.png`。深度 3 是標準體檢，沒有跑 `scripts/anti-patterns.js`（只在「深」時跑）。

| 維度 | 分數 | 依據 |
|---|---|---|
| 視覺層級 | 4 | 每頁一個 H1，主要按鈕藍色，是列表和表單最顯眼的元素 |
| 一致性 | 2 | 主要按鈕 4px、次要 12px（F15）；詳情頁「工單」、其他頁「訂單」（F3） |
| 排版節奏 | 2 | 手機上固定頁尾 120px 沒有留白，出錯後蓋住送出按鈕（F17）；長名稱撐出橫捲（F16） |
| 回饋 | 1 | 設定沒存（F11）；列表 API 失敗一直「載入中…」（F19）；離線送出沒反應（F20）；500 跳到找不到頁面（F22）；沒有送出中狀態，連點建兩筆（F6） |
| 文案 | 2 | 驗證錯誤只寫「發生錯誤」（F2）；「工單／訂單」混用（F3）；「#undefined」「NT$ 非數值」（F13） |
| 效率 | 3 | 建單一頁完成；篩選重新整理就消失（F10），草稿上一頁就沒了（F7），登入後不回原頁（F14） |
| 質感 | 3 | 乾淨；空狀態只剩表頭（F9），提示字對比 1.56:1（F21），🗑 是 DIV 裡的 emoji（F4），導覽觸控目標太小（探測 18 處） |

## 前五個改進

1. 每個寫入動作要有送出中、成功、失敗三種狀態，送出中停用按鈕（F6、F11、F19、F20、F22）
2. 驗證訊息寫清楚哪個欄位、為什麼錯，前端擋下負數（F2、F5）
3. 手機版替固定頁尾留出等高的底部空間，或改成不固定；長字串要能換行（F17、F16）
4. 補上空狀態和找不到資料的頁面（F9、F13）
5. 刪除改成 `<button aria-label="刪除訂單 #n">`，確認框加 `role="dialog"`、支援 Esc、焦點移入；統一圓角與用詞（F4、F18、F15、F3）
