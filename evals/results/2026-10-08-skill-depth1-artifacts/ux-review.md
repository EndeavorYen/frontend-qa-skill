## S1 登入
- 整體 3：帳號、密碼、登入按鈕和「請輸入帳號與密碼」看得懂，空白送出也說得清楚。扣分是頁尾「說明」「聯絡我們」（`a[href="#/help"]`、`a[href="#/contact"]`）點了仍停在登入，登入後則是「找不到頁面」（F13）。要到 4：這兩個連結要進得去，或先拿掉。

## S2 訂單列表
- 整體 2：「已完成」按下後仍混著待處理訂單（F10），API 失敗時 `#list` 停在「載入中…」而且恢復網路也不會自己好（F2）。刪除只有 🗑（F6）；刪除 API 失敗時對話框會關掉、列還在，也沒有錯誤（F20）。要到 4：篩選結果要和按鈕一致，失敗時要有錯誤和重試。

## S3 訂單詳情
- 整體 2：正常的 #1 看得到客戶和金額，但標題寫「工單」而列表寫「訂單」（F17）。沒有 note 的 #3 會丟 TypeError，備註是空白（F4）。不存在或 API 500 時主文出現「工單 #undefined」和「NT$ 非數值」（F15）。要到 4：缺資料和讀取失敗都要講人話，並和列表用同一個名字。

## S4 建立訂單
- 整體 2：欄位齊，小計會跟著變，但連點「送出訂單」會建兩筆（F1），失敗只寫「發生錯誤」（F8），0、1.5 和負單價存得進去（F9）。「數量必須是正整數」幾乎看不見（F7）。要到 4：送出只能成功一次，錯誤要指到欄位，非法數字在送出前就被擋下。

## S5 設定
- 整體 2：顯示名稱、每頁筆數、Email 通知都在，但「儲存」沒有請求、沒有提示，重新整理後名稱回到 `qa-user`（F14）。要到 4：儲存後看得到成功或失敗，重新整理還在。

## S6 說明
- 整體 1：登入後 `/#/help` 的主文只有「找不到頁面」（F13），這個畫面沒有完成它的任務。要到 4：放上真正的說明，或不要從頁尾連過來。

## S7 聯絡我們
- 整體 1：登入後 `/#/contact` 同樣只有「找不到頁面」（F13）。要到 4：放上聯絡方式，或拿掉連結。

## 最值得做的 5 項改善

1. **建立訂單只能送出一次，而且錯誤要指到欄位**
   - 現況：連點會建兩筆（F1）；空欄位或空白客戶名稱只顯示「發生錯誤」（F8）；數量 0、小數和負單價會存成訂單（F9）
   - 建議：送出後停用按鈕直到回應回來；正整數和單價在離開欄位時就檢查，訊息放在該欄下面
   - 預期效果：不會再多下一筆，使用者知道要改哪一欄。建立訂單的整體分數有機會到 4
2. **列表失敗時不要停在「載入中…」**
   - 現況：API 500、離線、401 都一直轉圈，網路恢復也不會自己再抓（F2）
   - 建議：換成錯誤說明和「再試一次」；401 則回到登入
   - 預期效果：主要畫面不會看起來像當掉。列表整體有機會到 3 以上
3. **「已完成」只顯示已完成的訂單**
   - 現況：按鈕已按下，列表仍包含待處理（F10）
   - 建議：用和「待處理」同一套狀態值過濾；空的「已取消」改成一句話說明（F11）
   - 預期效果：篩選可以拿來找單，而不是讓人懷疑狀態欄
4. **設定的「儲存」要真的留下**
   - 現況：按了沒有請求、沒有提示，重新整理後名稱回到舊值（F14）
   - 建議：寫入後顯示「已儲存」，失敗時留在表單並說明原因
   - 預期效果：設定頁的主要任務做得到
5. **頁尾連結和不存在的訂單不要落到壞頁**
   - 現況：說明和聯絡我們是「找不到頁面」或被送回登入（F13）；不存在的訂單和詳情 API 500 顯示 undefined、「非數值」（F15）；建立失敗則進 `#/orders/undefined`（F3）
   - 建議：沒有內容的連結先拿掉；讀不到訂單時用「找不到這筆訂單」和回列表，不要把 undefined 畫出來
   - 預期效果：走錯網址時知道下一步，而不是看到壞掉的工單
