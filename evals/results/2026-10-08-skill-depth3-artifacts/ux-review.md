# UI/UX 體檢

程度：標準。分數來自測試輪的實際操作。3 分以下附證據。看過的桌機全頁圖：`shots/S1-desktop.png` 到 `shots/S5-desktop.png`。

## S1 登入

| 維度 | 分數 | 說明 |
|---|---|---|
| 視覺層級 | 4 | `h1`「登入」與 `.btn-primary`「登入」是頁面上唯一的動作，不用找。 |
| 一致性 | 3 | 登入鈕圓角 4px，登入後的「登出」「取消」是 12px（F19）。 |
| 排版節奏 | 3 | 表單靠左，右半與下方是大片空白（`shots/S1-desktop.png`）。要到 4：表單在視窗裡水平置中，上下留白收斂。 |
| 回饋 | 4 | 空白送出時 `#err` 顯示「請輸入帳號與密碼」，看得到也說得清楚。 |
| 文案 | 3 | 「帳號」「密碼」「登入」清楚。頁尾「說明」點下去是「找不到頁面」（F14）。 |
| 效率 | 4 | 兩個欄位加一個按鈕，登入後直接到訂單列表。 |
| 質感 | 3 | 空白太多，主要按鈕相對畫面很小，看起來還沒排完（`shots/S1-desktop.png`）。 |

## S2 訂單列表

| 維度 | 分數 | 說明 |
|---|---|---|
| 視覺層級 | 4 | 右上 `a.btn-primary`「建立訂單」是唯一實心藍鈕，篩選是白底 pill，主次分得開。 |
| 一致性 | 2 | 這一頁叫「訂單」，點進 #1 標題變成「工單」（F18）。主要按鈕 4px、篩選按鈕 12px（F19）。 |
| 排版節奏 | 3 | 表格欄位對齊，長客戶名稱在 `.truncate` 截斷。列號連結只有約 7×18px，垃圾桶 34×23px（F12），掃過去很輕、也不好點。 |
| 回饋 | 2 | 「已完成」按下去是按下狀態，列表仍混著待處理（F2）。「已取消」只剩表頭（F15）。API 失敗時停在「載入中…」（F3）。 |
| 文案 | 3 | 欄名清楚。刪除只有 🗑，沒有「刪除」兩個字（F7）。 |
| 效率 | 3 | 有狀態篩選，但「已完成」不能用，找已完成的單要自己掃整表（F2）。沒有搜尋。設定寫每頁 10 筆，這裡一次 14 筆（F17）。 |
| 質感 | 3 | 表格本身乾淨。垃圾桶和列號太小，加上測試列裡的負小計，整體還不像能拿去對客戶的清單。 |

## S3 訂單詳情

| 維度 | 分數 | 說明 |
|---|---|---|
| 視覺層級 | 2 | `dt` 標籤和值同一字級、同一字重往下疊，「客戶」和「王小明」要讀完才分得出誰是標籤（`shots/S3-desktop.png`）。頁面上沒有下一步動作。要到 4：標籤改小改淡，值留在右邊或下一行用較重的字。 |
| 一致性 | 2 | 標題「工單 #1」，導覽仍是「訂單」（F18）。#2 備註是「（無備註）」，#3 備註是空白還丟例外（F8）。 |
| 排版節奏 | 3 | 卡片有對齊，但標籤和值貼很近。390px 時 #3 的長名稱把頁面撐到 528px（F11）。 |
| 回饋 | 2 | 打開 #3 時 console 有 TypeError，備註沒有替代文字（F8）。這頁也不能改狀態，看完只能「← 回列表」。 |
| 文案 | 2 | 「工單」和空白備註會讓人以為資料壞了（F8、F18）。 |
| 效率 | 3 | 只讀。要改或刪，得回列表找垃圾桶。 |
| 質感 | 3 | 卡片有圓角和留白，但資訊層級像 debug 輸出，不像一張工單。 |

## S4 建立訂單

| 維度 | 分數 | 說明 |
|---|---|---|
| 視覺層級 | 4 | 「建立訂單」標題、即時「小計」、實心「送出訂單」連成一條，取消是次要按鈕。 |
| 一致性 | 3 | 同一列的「取消」圓角 12px、「送出訂單」4px（F19，`shots/S4-desktop.png`）。 |
| 排版節奏 | 4 | 欄位寬度一致、間距規律。390px 時送出鈕仍在視窗內。 |
| 回饋 | 2 | 空白送出只寫「發生錯誤」（F10）。離線送出畫面不動（F5）。HTTP 500 跑去 `#/orders/undefined`（F4）。連點會變成兩筆（F1）。 |
| 文案 | 2 | `.hint`「數量必須是正整數」對比 1.56:1（F13），而且 0 和負數仍送得出去（F9）。錯誤句沒有說要改哪一欄（F10）。 |
| 效率 | 4 | 一頁填完，小計隨數量和單價變。合法資料送出後會到詳情。 |
| 質感 | 3 | 結構清楚，但提示看不見、兩顆按鈕圓角不一樣，失敗時又不說原因，還不到能放心打單的程度。 |

## S5 設定

| 維度 | 分數 | 說明 |
|---|---|---|
| 視覺層級 | 4 | 三個設定加一顆「儲存」，沒有第二個同等級的動作。 |
| 一致性 | 3 | 「儲存」圓角 4px，和列表的次要按鈕 12px 不同（F19）。勾選框約 13×13px，旁邊的輸入框高 41px（F12）。 |
| 排版節奏 | 3 | 和建立頁一樣靠左、下方大片空白（`shots/S5-desktop.png`）。 |
| 回饋 | 1 | 按「儲存」沒有文字、沒有請求，重新整理後名稱回到 `qa-user`、筆數回到 10（F6）。這個畫面的主要任務做完是錯的結果。 |
| 文案 | 4 | 「顯示名稱」「每頁筆數」「有新訂單時寄 Email 通知我」都是人話。 |
| 效率 | 2 | 看起來一步就能存，存了等於沒存，使用者會再按一次然後離開（F6）。每頁筆數也沒有反映在列表（F17）。 |
| 質感 | 3 | 表單像完成品，但儲存沒有反應之後就不可信。 |

## 最值得做的 5 項

1. 建立訂單的送出要只寫入一次，失敗時留在表單並寫出原因。現在連點會有兩筆（F1），500 會進到 `#/orders/undefined`（F4），離線則完全沒反應（F5），空白送出只寫「發生錯誤」（F10）。
2. 列表的篩選和載入狀態要跟資料一致。「已完成」按下後仍混著待處理（F2）；API 失敗或離線時停在「載入中…」（F3）；「已取消」沒有空狀態（F15）。
3. 「儲存」要真的留下顯示名稱和每頁筆數，並在按鈕旁顯示已儲存（F6）。列表要照每頁筆數分頁，而不是一次把 14 筆都畫出來（F17）。
4. 數量、單價依畫面上的規則擋下，並把「數量必須是正整數」改成看得到的顏色（F9、F13）。0、負數、負單價現在都會變成訂單。
5. 刪除要能只用鍵盤完成：垃圾桶進 Tab 順序、有「刪除」名稱，確認框把焦點留在框裡，Esc 等於取消（F7）。詳情的長客戶名稱要換行（F11），缺備註時不要丟例外、改顯示「（無備註）」（F8）。
