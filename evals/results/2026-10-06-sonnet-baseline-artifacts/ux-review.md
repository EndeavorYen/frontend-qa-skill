## 最值得做的 5 項改善

照「對使用者的影響 ÷ 改動大小」排序：

1. **修正訂單資料的正確性：已完成篩選、欄位驗證、防重複送出**
   - 現況：「已完成」顯示全部（F4）、負數／0／小數都能建立（F9、F12）、連點建立多筆（F11）
   - 建議：修正篩選條件；送出前驗證 qty 為正整數、price ≥ 0 並在欄位旁顯示錯誤；送出時按鈕進入 loading／disabled，伺服端也以 idempotency key 防重
   - 預期效果：資料可信；回饋、效率兩個維度預期可到 4 分
2. **補齊四種狀態：載入失敗、空狀態、成功、失敗提示**
   - 現況：500／401／斷網時永遠載入中或毫無反應（F18、F20、F21、F38）；空列表無說明（F5、F19）；刪除／建立成功無回饋（F15）
   - 建議：用同一組 `<ErrorState onRetry>`、`<EmptyState cta>` 與 toast；`fetch` 一律檢查 `res.ok`；401 導回登入
   - 預期效果：S2、S4 的「回饋」從 1 提升到 4
3. **設定頁真的儲存，或在未完成前先移除**
   - 現況：儲存無作用且沒有請求（F14），「每頁筆數」無效（F16）
   - 建議：串 API 並顯示「已儲存」、更新 header 名稱；列表實作分頁；功能未備齊前隱藏該頁
   - 預期效果：消除「按了沒反應」的信任問題
4. **手機版面：固定頁尾、表格、點擊目標**
   - 現況：頁尾蓋住送出鈕（F23）、表格被截（F26）、目標過小（F36、F25）
   - 建議：`main` 加 `padding-bottom` 等於頁尾高度或取消 `position:fixed`；手機改卡片列表；按鈕與 icon 目標至少 44×44（🗑 改 `<button aria-label>`，F6）
   - 預期效果：排版節奏、效率在手機尺寸可到 4
5. **修好死連結與不存在資料的處理**
   - 現況：說明／聯絡我們是 404（F2）、`#/orders/999` 顯示 undefined（F1）、404 沒出口（F34）
   - 建議：補上這兩頁（或移除連結）；詳情頁依 HTTP 404 顯示「找不到這筆訂單」並提供回列表；404 頁加「回訂單列表」
   - 預期效果：新手不會在求助時走入死路
