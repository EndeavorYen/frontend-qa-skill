## 摘要
- 嚴重度：P0 ×0、P1 ×8、P2 ×15、P3 ×14（共 37；F22 已撤回，編號不補）
- 覆蓋率（含體檢欄，共 91 格）：✅ 63 / ➖ 26 / ⛔ 2
- 一句話結論：這個 app 的畫面簡潔，但資料正確性與錯誤處理都不可信：篩選會給出錯的結果、負數與重複訂單都能建立、設定頁的儲存沒作用、任何 API 失敗都會讓畫面卡住或顯示 `undefined`，而且手機上送出鈕被固定頁尾蓋住。

## 最嚴重的 5 個問題
1. F4 [P1][bug] 「已完成」篩選會顯示全部訂單（含待處理）— 使用者看到的完成清單是錯的
2. F11 [P1][bug] 連點「送出訂單」會建立多筆重複訂單，按鈕沒有 loading／停用 — 800ms 的請求時間內就能重複送出
3. F9 [P1][bug] 可以送出負數量（-3）建立負金額訂單（0、負單價也行）— 髒資料直接進列表
4. F14 [P1][邏輯] 設定頁「儲存」沒有請求、沒有回饋、重新整理就還原 — 使用者以為存了其實沒有
5. F18 [P1][斷點] 訂單 API 回 500／401 時列表永遠「載入中…」且不會導回登入；與 F20（建立訂單 500 時跳到「找不到頁面」並丟失資料）、F1（不存在訂單顯示「工單 #undefined」）、F23（手機上送出鈕被頁尾蓋住）同為 P1，共同點是缺少錯誤處理與響應式留白
